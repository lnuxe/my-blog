浏览器自动化2 个仓库

把重复的点击交给机器。共同点是：确定性优先，能被代码表达的规则就不要交给模型。

  • starmerx_listing

    Python

    基于 Playwright 的确定性浏览器自动化，实现「产品池 → 加入上架计划 → 图片/价格校验 → 批量上架」全流程（MVP：圣诞花环单品类）。

    • Python 3.13 + Playwright 1.62 做确定性 DOM 操作；阿里云通义千问 Qwen 仅在规则层失败时兜底
    • 登录用钉钉扫码 + storageState 持久化，登录态约 2 天过期，过期自动提醒重扫
    • 利润试算引擎用有界二分防死循环：最多 20 次迭代，未命中即报「需人工介入」
    • 默认干运行（--dry-run），确认后才用 --no-dry-run 真正执行
    • 勘察优先：新页面先跑 scripts/probe_product_pool.py 确认选择器，再进执行模式；每次点击后用 DOM 状态（input value / checkbox checked）验收，失败即中止
    GitHub

  • ldm / wechat-mcp

    JavaScript

    macOS 上通过 MCP 操作微信桌面版的示例服务器，把「发消息 / 读当前聊天」变成 Agent 可以调用的工具。

    • send-text-message：激活 Mac 微信，搜索联系人或群聊并发送文本
    • get-current-chat-text：读取当前聊天窗口里可见的文本内容
    • 底层用 AppleScript + osascript 控制微信，封装成 MCP 工具供 Cursor / Claude Desktop 调用
    • 仓库里附了 Vercel 部署与微信公众号服务器配置的完整说明，含内网穿透与超时排查
    GitHub 在线 Demo

Flutter · Dart2 个仓库

桌面与移动端的工具型应用，主要用 Flutter 写成，能在 Windows / macOS / Web 上打包产物。

  • EPF-Unlocker

    Dart

    Flutter 桌面工具，用于解锁 Excel（.xlsx）与 PDF 文件保护，支持单文件、批量与定时自动解锁。

    • 单文件解锁支持拖拽或选择；批量解锁递归扫描目录；定时自动解锁可监控目录并处理新文件，间隔 1–120 分钟
    • Excel 解锁原理：把 .xlsx 当 ZIP 解压，移除 xl/worksheets/*.xml 里的 <sheetProtection> 标签后重新打包
    • PDF 解锁走 syncfusion_flutter_pdf，也可用外部 qpdf 或 Python pypdf 兜底
    • 不支持旧版 .xls（二进制格式），程序会提示先用 Excel 另存为 .xlsx
    • Apache-2.0 许可，GitHub Actions 跑 flutter analyze、flutter test 与多平台构建
    GitHub

  • Imitate-DJI-HOME

    Flutter

    Flutter 项目，模仿大疆 Home iOS App 的界面与交互实现。

    • 用 Flutter 复刻大疆 Home iOS App 的页面结构与视觉风格
    • 作为 Flutter 布局与自定义绘制的练习项目持续迭代
    GitHub

AI · Agent 技能3 个仓库

给 Cursor / Claude Code 用的技能包与 RAG Demo：重点是边界、预算与可解释，而不是「让模型自由发挥」。

  • pickled-fish（泡菜鱼）

    HTML

    macOS 微信本机聊天导出 + 心理/关系知识库 + 文件系统 RAG，跑在 Cursor Agent 上的技能包。

    • 导出管线 skills/wechat-mac-export：面向 WeChat 4.1.10+，用 LLDB 抓 passphrase 再 PBKDF2 解密 db_storage/*.db
    • wxecho export "昵称" 写出 ~/Downloads/wxecho/<联系人>/chat.txt，也支持 json / csv
    • 整段聊天分析：时间线、话轮、冷场与转折点统计，避免只看截图断章取义
    • Index-first 文件系统 RAG：REGISTRY → PACK.md → rg 关键词 → Read 段落，同轮最多深读 2 个 pack 并强制标注 packs_used
    • MIT 许可；DISCLAIMER 写明仅限本人数据、非诊疗、禁止骚扰
    GitHub

  • flutter-defect-triage

    Shell

    Cursor / Claude Code 用的缺陷分诊 skill，面向 Flutter Web、App WebView、小程序 H5、多宿主 JSBridge 等高坑密度场景。

    • 核心理念「先对齐坑，再写修复」：未对齐前不写修复代码
    • 强制四步：选业务包 → 扫坑（先读 RAG 索引再打开对应 Case）→ 坑点对齐（机制表交用户确认）→ 窄修复（Scope Gate 四维 + 合入后回填 Case）
    • 双层结构：全局 skill 放流程、模板与跨仓 Case；项目 overlay 放本仓路径、协议与发布 slot
    • 示例产品 Harbor Club 是虚构的，只演示 Tab 收缩、数据路径分裂、宿主权限三类真坑
    • MIT 许可，setup 一条命令同时装到 Cursor 与 Claude Code
    GitHub

  • rag-cs-bot

    TypeScript

    基于 Dify RAG 的电商客服自动化 Demo：TikTok Shop 售前 AI 客服 + 浏览器自动化回填。

    • 链路：本地 Dify + RAG 知识库 → Flask 客服前端代理 → UI-TARS 浏览器自动化读取消息 → 调 Dify API 自动回复
    • 知识库只放售前内容（产品 / 发货 / 物流 / 价格 / 尺码），售后不喂给 AI，从机制上强制转人工
    • cs_web/app.py 的 clean_answer() 用正则剥离 DeepSeek 的思考过程，两种格式都处理
    • 踩坑记录：Dify 知识库索引会因 SQLAlchemy 连接池耗尽而停滞，需要控制并发、串行处理文档
    GitHub
